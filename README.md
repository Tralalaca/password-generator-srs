# Генератор сложных паролей — требования и план разработки

Репозиторий содержит техническое задание лабораторной работы № 1, план разработки лабораторной работы № 2 и браузерное приложение лабораторной работы № 3. Генератор создаёт пароли по выбранным параметрам и показывает ориентировочную оценку их стойкости.

## Запуск и проверка

Для запуска без установки зависимостей выполните `python -m http.server 8000` в корне репозитория и откройте `http://localhost:8000`. Для автоматической проверки нужен Node.js 20 или новее: `node --test tests/generator.test.js`. Приложение состоит из `index.html`, `style.css` и `script.js`.

Пароль создаётся через `crypto.getRandomValues` в безопасном контексте браузера (HTTPS или localhost), не отправляется по сети и не сохраняется в локальном хранилище. В `localStorage` записываются только настройки генерации. Для копирования нужен доступ к буферу обмена; при отказе пароль остаётся на экране. Оценка `H = L × log₂(N)` ориентировочная и не гарантирует защиту от взлома.

Проверки Node.js покрывают граничные длины, наборы символов, исключения, пороги оценки, сохранение настроек и ошибки хранилища и буфера обмена. В Headless Chrome 158 на `localhost` проверены генерация, копирование, восстановление настроек и ширина 360 пикселей: горизонтальной прокрутки нет даже с паролем из 128 символов. Полная матрица браузеров и измерение на устройстве с 2 ГБ ОЗУ требуют отдельной приёмки.

## Планирование разработки

План рассчитан на 28 октября — 11 декабря 2026 года. В GitHub опубликованы 24 задачи, четыре контрольные точки, публичный Project Roadmap и страница Wiki. Задачи содержат оценки трудозатрат, основные роли и зависимости. Один участник выполняет роли менеджера проекта, дизайнера, frontend-разработчика и QA-инженера. Backend-разработка не требуется: по ТЗ пароль создаётся в браузере и не передаётся на сервер.

## Область требований

ТЗ описывает генерацию пароля длиной от 6 до 128 символов, выбор наборов символов, исключение похожих символов, копирование, ориентировочную оценку стойкости, сохранение настроек и русскоязычный интерфейс. Для генерации требуется криптографически стойкий источник случайности; пароли не сохраняются и не отправляются на сервер.

Связь требований и задач двусторонняя: каждый раздел ТЗ ссылается на соответствующую Issue, а в каждой Issue должна быть ссылка на раздел ТЗ.
